# 远程控制爬虫系统 - 数据流改造文档

## 一、当前架构分析

### 1.1 现有数据流

```
Web端 --创建任务--> Server端 --下发任务--> Client端
                                            |
                                     爬取数据(本地保存)
                                            |
                                     report_result(仅元数据)
                                            |
                                   Server端(仅存products数组)
```

### 1.2 现有问题

| 编号 | 问题 | 说明 |
|------|------|------|
| P1 | Client端JSON数据未返回Server | tasks.json、batch.json 仅保存在客户端本地 |
| P2 | Server端无完整采集数据 | 只存了 products 元数据(title/url/status)，无实际商品详情 |
| P3 | Web端无法获取采集结果 | Server 没有提供 Web 端获取任务数据的接口 |
| P4 | task_id 未贯穿全链路 | Web端创建任务后无法用 task_id 追踪整个采集过程 |
| P5 | 无实时通知机制 | Web端无法实时获知任务状态变化 |

---

## 二、改造目标

### 2.1 目标数据流

```
Web端 --创建任务(task_id)--> Server端 --下发任务(task_id)--> Client端
     ^                          |                              |
     |                          |                     爬取数据(本地保存)
     |                          |                              |
     |                          |                   上报JSON数据(task_id)
     |                          |                              |
     |                   Server端存储完整数据                     |
     |                          |                              |
     +----轮询/WebSocket--------+                     Client端继续等待新任务
```

### 2.2 核心设计原则

1. **task_id 贯穿全链路**：从 Web 创建任务到 Client 返回结果，task_id 是唯一标识
2. **JSON 数据完整回传**：Client 端的采集数据通过 JSON 格式完整返回 Server
3. **Server 端集中存储**：所有采集数据统一存储在 MongoDB
4. **Web 端可查询可监听**：Web 端通过 API 查询结果，可选 WebSocket 实时推送

## 三、task_id 贯穿全链路设计

### 3.1 task_id 生成规则

```
格式: task_{timestamp}_{random}
示例: task_20260425143000_a3f2
```

由 Server 端在创建任务时生成，确保全局唯一。

### 3.2 task_id 流转路径

```
┌─────────┐    POST /api/tasks     ┌─────────┐   heartbeat响应    ┌─────────┐
│  Web端  │ ──────────────────────> │ Server  │ ─────────────────> │ Client  │
│         │ <────────────────────── │         │ <───────────────── │         │
│         │   返回 task_id          │         │   携带 task_id     │         │
│         │                         │         │                    │         │
│         │                         │         │ <───────────────── │         │
│         │                         │         │  task_report       │         │
│         │                         │         │  (携带 task_id)    │         │
│         │                         │         │                    │         │
│         │                         │         │ <───────────────── │         │
│         │                         │         │  task_result       │         │
│         │                         │         │  (携带 task_id)    │         │
│         │                         │         │                    │         │
│         │  GET /api/tasks/{id}    │         │                    │         │
│         │ ──────────────────────> │         │                    │         │
│         │ <────────────────────── │         │                    │         │
│         │   返回完整结果           │         │                    │         │
└─────────┘                         └─────────┘                    └─────────┘
```

### 3.3 各端 task_id 使用方式

| 端 | 获取 task_id 方式 | 使用场景 |
|----|-------------------|----------|
| Web | 创建任务时 Server 返回 | 轮询查询任务状态、获取结果 |
| Server | 自己生成 | 存储任务、分配任务、关联数据 |
| Client | 心跳响应中获取 | 上报进度、提交结果 |

def report_result(self, task_id: str, result: dict):
    data = {
        "client_id": self.client_id,
        "task_id": task_id,
        "result": result,
        "timestamp": datetime.now().isoformat()

    try:
        self.session.post(

            json=data, timeout=30

## 五、Server 端改造

### 5.1 修改 task_result 接口

**当前：** 只接收 batch_id 和 products

**改造后：** 接收完整的 result 对象

```python
@bp.route('/task_result', methods=['POST'])
def task_result():
    from flask import request, jsonify
    from app.models import update_task_result, update_task_progress, add_log
    
    data = request.get_json()
    client_id = data.get('client_id')
    task_id = data.get('task_id')
    result = data.get('result', {})
    
    if not task_id:
        return jsonify({"code": 400, "message": "task_id is required"}), 400
    
    update_task_result(task_id, result)
    update_task_progress(task_id, "completed")
    add_log(task_id, "info", f"任务完成")
    
    return jsonify({
        "code": 200,
        "message": "success",
        "data": {
            "task_id": task_id
        }
    })
```

## 六、Web 端获取数据方案

### 6.1 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **轮询(Polling)** | 实现简单，无需额外依赖 | 有延迟，浪费请求 | 任务量少，实时性要求不高 |
| **长轮询(Long Polling)** | 比轮询更实时 | Server 端需保持连接 | 中等实时性要求 |
| **WebSocket** | 实时双向通信 | 实现复杂，需维护连接 | 高实时性要求 |

### 6.2 推荐方案：轮询 + WebSocket 可选

**阶段一（快速实现）：轮询**

Web 端使用 task_id 定期查询任务状态：

```javascript
// Web 端轮询示例
async function pollTaskStatus(taskId) {
    const interval = 3000; // 3秒轮询一次
    
    while (true) {
        const response = await fetch(`/api/tasks/${taskId}/progress`);
        const data = await response.json();
        
        if (data.data.status === 'completed') {
            // 任务完成，获取完整结果
            const result = await fetch(`/api/tasks/${taskId}/result`);
            return result.json();
        }
        
        if (data.data.status === 'failed') {
            throw new Error(data.data.error);
        }
        
        // 更新进度显示
        updateProgress(data.data.progress);
        
        await sleep(interval);
    }
}
```

**阶段二（可选升级）：WebSocket**

Server 端添加 WebSocket 支持，主动推送任务状态变化：

```python
# Server 端 WebSocket 推送（使用 flask-socketio）
from flask_socketio import SocketIO, emit

socketio = SocketIO(app, cors_allowed_origins="*")

@socketio.on('subscribe_task')
def handle_subscribe(task_id):
    """Web 端订阅任务状态"""
    pass

# 在任务状态变更时推送
def notify_task_update(task_id, status, progress=None):
    socketio.emit('task_update', {
        'task_id': task_id,
        'status': status,
        'progress': progress
    }, room=task_id)
```

### 6.3 Web 端 API 请求流程

```
1. 创建任务
   POST /api/tasks
   请求: { "instruction": "start_crawl", "params": { "shop_url": "..." } }
   响应: { "code": 200, "data": { "task_id": "task_xxx", "status": "pending" } }
   
2. 轮询进度（使用 task_id）
   GET /api/tasks/{task_id}/progress
   响应: { "code": 200, "data": { "status": "running", "progress": {...} } }
   
3. 获取结果（任务完成后）
   GET /api/tasks/{task_id}/result
   响应: { "code": 200, "data": { "task_id": "task_xxx", "result": {...} } }
```

## 九、OSS 字段预留

当前 JSON 数据中预留 `oss_url` 字段，后续集成 OSS 时只需：

1. Client 端上传文件到 OSS
2. 将 OSS URL 填入 `oss_url` 字段
3. 上报结果时 `oss_url` 自动包含在 JSON 中
4. Server 端和 Web 端无需改动

```json
{
    "images": [
        {
            "filename": "img1.webp",
            "local_path": "D:/.../img1.webp",
            "oss_url": "https://bucket.oss-cn-hangzhou.aliyuncs.com/crawl/task_xxx/img1.webp"
        }
    ]
}
```
